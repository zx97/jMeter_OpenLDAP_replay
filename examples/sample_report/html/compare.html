Legend — how to read this report

RATE/s
Throughput: number of operations completed per second.
AVGms
Average response time of the LDAP server, in milliseconds.
p50 / p95 / p99 (ms)
Response time percentiles: the value under which 50% / 95% / 99% of the operations completed. Example: p95 = 41 ms means 95% of the operations took 41 ms or less. They reveal the tail of the latency distribution: the gap between p50 and p99 grows when the server starts to saturate.
MAXms
Slowest single operation observed.
INFRA_ERR
Infrastructure errors: operations where LDAP did not reply at all (network failure, timeout, connection refused). The only real failures; everything else counts as “LDAP replied”.
Transactions per second
Throughput of all operations combined (BIND + SRCH + CMP + UNBIND + ABANDON, i.e. every operation type of the replay): number of completed transactions per second, bucketed over short intervals. A plateau means the server cannot go faster.
Average transaction response time (ms)
Mean response time of all operations per interval. Read it together with Transactions per second: when throughput plateaus while this curve rises, the server is saturated.
Concurrent connections
Number of LDAP connections in flight at the same time (the load level of the test).
Transaction summary table
Per operation type (BIND, SRCH, CMP, UNBIND, ABANDON): total count, minimum, average, maximum, standard deviation, 90th percentile, and the number of passed / failed transactions. The 90% column follows the LoadRunner Transaction Summary convention; the comparison charts additionally show p95 / p99.
Elapsed time on the X axis
All charts use the test duration, starting from zero, formatted as mm:ss (e.g. 2:35 = 2 minutes 35 seconds after the start of the test), never the clock time of the logs.

Chart colours (Behaviour over time): green bars = operations per minute (load), amber dots and line = average latency (ms), red ticks = infrastructure errors. Hover a bar for details.
